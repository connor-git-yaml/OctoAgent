# F149 Claude Design 最终谱系清理

## 目标

在 Claude Design 项目 `851e3fb2-2b5b-4251-a095-8a678b1b7fec` 中完成一次最终窄返修：

- 以最早期页面 `1a 对话工作台（主视图）` 的视觉语言为最高视觉权威；
- 保留已冻结的 F149 功能、状态、普通语言、无障碍和响应式合同；
- 删除或替换后续产生的高辐射、大 Hero、过度留白、卡片膨胀等不符合早期工作台风格的中间方案；
- 不把现有 Web 的旧外观当成模板，不为了实现方便降低设计质量；
- 不改变产品功能、协议、状态语义或 Web/iOS 产品边界。

## 必须保留

以下内容不得删除、改名或合并：

1. 早期视觉权威页面：
   - `1a 对话工作台（主视图）`
   - `1b 全局任务浮层`
   - `1c 启动页`
2. 既有 page 2、page 3 的远程访问、状态与工件详情事实。
3. F149 最终 20 个唯一 frame 名称。
4. `Shared-States`、`Advanced-Pattern`、`References`。
5. 20 行逐 frame 验收表。
6. 10 surface × 7 状态矩阵。
7. 全部已冻结行为：
   - loading、empty、recoverable error、origin 403、not-found、disconnected、409；
   - unknown/historical/extended 事件仅进入默认收起的高级诊断；
   - 403 只表示资源权限不足，不在 F149 内提供重新登录；
   - Web 390px 仅为窄窗口健壮性，不是手机产品入口；
   - 手机产品只走原生 iOS App。

## 视觉权威

最终 Desktop 与 390px Web frames 应采用 `1a` 的共同视觉语言：

- 近黑背景、紧凑三栏工作台；
- 清晰但克制的蓝黑标题区；
- 低辐射、连续、较小圆角的卡片；
- 较高但可读的信息密度；
- 以内容层级、留白和排版形成张力，而不是依赖大面积渐变或发光；
- 主要动作使用清晰绿色强调，次要动作保持克制；
- 任务、会话、运行状态和工件必须像同一工作台的一部分，而不是互不相关的营销卡片；
- 保留至少 44px 可交互目标、键盘焦点、可访问名称和窄窗口可用性。

以下视觉做法不得出现在最终交付 frame：

- 大面积 radial gradient；
- 高亮光晕或霓虹背景；
- 为单一页面标题占用过高空间的巨大 Hero；
- 大量孤立圆角卡片造成的“卡片墙”；
- 稀疏到削弱工作台信息密度的过度留白；
- Spotify Design System、Figtree 外链或第二主题；
- 以当前旧 Web 页面为视觉模板。

## 允许删除的对象

仅允许删除以下对象：

- 与最终 frame 重复的隐藏副本；
- 无验收名称、无 References 引用、无功能合同的中间探索 frame；
- 已被 `1a` 视觉语言替代的高辐射、大 Hero、卡片墙变体；
- Spotify Design System 残留和其不再使用的 bundle/font 引用。

不得删除早期 page 1–3、20 个必需 frame、状态矩阵、验收表或任何协议证据。

## 执行要求

1. 先列出候选删除对象的 frame ID、名称、可见性、引用关系和删除理由。
2. 逐项确认候选不属于“必须保留”清单。
3. 先把必需最终 frame 调整到 `1a` 视觉语言，再删除确认无用的中间对象。
4. 不新增功能、协议、状态、认证入口或移动 Web 产品入口。
5. iOS 只继承共同视觉语言；不得在本设计文件中用 WebView 或 Web 组件结构伪装原生 iOS 设计。
6. 完成后输出：
   - 最终保留 frame 清单；
   - 删除/替换 frame 清单；
   - 每项视觉偏离的必要原因；
   - Spotify/Figtree/外部 bundle 计数；
   - 导出文件路径、bytes、SHA-256 和项目 UUID。

## 完成判定

只有同时满足以下条件才可声明完成：

- 必需 frame 与状态合同完整；
- 最终 frame 视觉与 `1a` 同源；
- 中间丑化方案已删除或不再作为最终 frame；
- 不存在 Spotify/Figtree/第二主题残留；
- 云端文件真实保存；
- 新导出文件已不可变回存并通过 frame、状态、资产和 SHA 机械核验；
- Web 像素基线与最终设计方向一致；
- 没有把 iOS 误写成手机浏览器产品。
